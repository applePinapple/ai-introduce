## 00:00–00:12.5｜从 VLA 执行到长程任务

之前，我们看到 Astra + π0.5，大模型监督，VLA 执行，这条路越来越行！

但机器人真正做一个长程任务，还有几个问题：

- 什么时候该调用 VLA？
- 什么时候用传统控制工具？
- 抓取失败了怎么重试？
- 下次又怎么样少犯同样的错误？

## 00:12.5–00:29｜RPent 与 Agent Runtime

最近清华牵头、多机构合作开源的 Recursive Physical Agent，简称 RPent，试着把这些环节装进同一套 Harness。

Astra + VLA + Harness 这条路线，开始有了更完整的系统形态。

机器人正在拥有自己的 Agent Runtime，也就是负责调度、检查任务和运行框架。[^runtime]

那么它怎么工作？

## 00:29–00:49｜Planner、Harness 与动作技能的分工

上层 Planner 可以接 GPT-6 Astra、Claude 这样的通用模型，负责理解当前画面和任务，读取执行反馈，并决定下一步调用什么能力。

中间的 Harness 负责调用工具，管理记忆和检查执行结果。

下面，则是一组可调用的动作技能，可以接入 π0.5、LingBot-VLA 等不同 VLA，也可以调用移动机械臂、调整姿态这样的传统控制工具。

最后连接到机器人本体。

## 00:49–01:02｜亮点一：VLA 变成了一项技能

这里的第一个亮点是：VLA 变成了一项技能。

比如让机器人拿起杯子，规划器可以先用传统工具，把手臂移到杯子旁边。到了真正需要抓取、处理接触的时候，再调用 VLA。

VLA 不是包办整个任务，而是专心做好它擅长的那一步。

## 01:02–01:16.5｜亮点二：执行检查与失败恢复

第二个亮点是：做完还要检查，失败还能恢复。

如果杯子没有拿起来，系统会重新看当前画面，判断问题出在哪，再调整机器人状态，有针对性地重试。

它不是一条 policy 从头跑到底，而是执行、检查、失败之后，再重新组织接下来的动作。

## 01:16.5–01:31.5｜亮点三：积累可复用的记忆

第三个亮点是：它开始有记忆了。

RPent 会保存验证过的执行策略，也会积累成功模式、失败情况和恢复办法。

这个记忆不是简单地背坐标。下次杯子换了地方，它仍然会重新看现场，重新绑定目标和空间位置，再借用过去积累下来的经验。

## 01:31.5–01:47｜视频所述的仿真评测结果

那么效果怎么样？

在 VLA 权重保持冻结的情况下，RPent 目前更新的 leaderboard 里，用 Codex 接入 GPT-6 Astra、开启 memory 的配置，在 LIBERO-PRO 八套任务上，成功率进一步推到 92.63%，800 次测试成功 741 次。[^libero]

目前公开的上述成功率来自仿真。

## 01:55.5–02:05.5｜四个部分如何连接

基础模型负责理解和规划。

Harness 负责调度、检查与恢复。

VLA 等技能负责动手。

执行数据和经验再回到系统里。

RPent 让这四块在一个开源框架里接了起来。
